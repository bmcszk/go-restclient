# Pitfalls (cost fix rounds — read before contracting work)

## CLI version + releases (binding)
- Version resolution ladder (research-verified pattern, kubectl/gh/goreleaser/gum): ldflags `-X main.version=` primary → BuildInfo fallback → `dev` default; kong var fed by ONE `resolveVersion()` helper, never a raw constant. No goreleaser in this repo — release binary is built with explicit ldflags, then `gh release create vX.Y.Z` (v-prefixed tag required by Go modules).
- NEVER trust `debug.BuildInfo.Main.Version` without an exact-semver guard (`^v?\d+\.\d+\.\d+$`): modern toolchains embed a pseudo-version (`vX.Y.Z-0.<date>-<sha>+dirty`) as Main.Version on plain `go build`, so the old `!= "(devel)"` check prints garbage. Real-tag installs and plain builds must both resolve correctly.
- Release notes style (USER SPEC, binding): super minimal, features only — never test counts, refactors, or stats sections.
- When a change is impl-only (tests untouchable), existing test assertions bound the design: check what they assert BEFORE choosing the fallback shape, not after the gate run.
- Linter-version drift breaks green code: a workflow pinning a linter to `:latest` (golangci-lint did v2.13→v2.14) can fail a tag or master run on UNCHANGED code — a fresh `revive` rule fired on a pre-existing multiline if-init. Root-cause as code fix when the fix is a trivial 3-line hoist (run the new linter locally first); never answer drift with `//nolint`, config edits, or version pins. Expect this on tag-push CI: master ran green days earlier with the older linter version.
- Tag-cut release procedure that worked end-to-end: confirm default-branch CI green at the exact HEAD SHA (`gh run list --workflow <wf> --branch master`), `git tag -s <tag> <sha>` with `SSH_AUTH_SOCK` exported, push tag, `gh release create <tag> --verify-tag --notes <features-only>`, then verify readback (`gh release view` + tag CI run). Remember the linter-drift trap above fires exactly here.
- Refactor PRs applying style rules follow one shape: one mechanism primitive per duplication family (`randomChoice` for N pick-or-fallback blocks), inline closures become named functions so the caller reads as the sequence, dedupe shared preambles in sibling entry points into one helper, strip narration comments keeping only why-comments. Gates before push: build, `golangci-lint run` (expect `0 issues.`), full `go test ./...`; report diff as net LOC delta per file. If a known-lint-drift hunk (above) is unmerged, include it so the branch lints standalone.
